## なぜ難しいのか

エージェントは、あなたが読むより速くコードを書きます。小さな依頼が大きな diff になって戻ってくることがあります。頼んでいない変更が入っていて、要約はすべて動くと書いています。すべての行を読むには時間がかかりすぎます。ざっと見るだけでは、間違いが通ります。

難しいのは、エージェントが何をするはずだったかを知ることです。それがなければ、ある変更が diff に入って当然なのか、誰も頼んでいない範囲なのか、見分けられません。

## diff で見る点

どの方法でレビューしても、次を見ます。

- **範囲。** 想定していなかったファイル。lockfile、マイグレーション、設定、名前の変更などです。
- **エラーの道筋。** 入力がない、呼び出しが失敗する、値が空のとき、何が起きるか。
- **依存とアクセス。** 新しいパッケージ、スクリプト、認証情報、または誰がデータを読めるか・変えられるかの変更。
- **テスト。** 変更を実際に動かしているテスト。要約に「通った」と一行あるだけでは足りません。

## 方法 1：git か pull request でレビューする

エージェントのブランチをメインブランチと diff するか、pull request を開いて、同僚の仕事を見るときと同じようにレビューします。どのエージェントでも、すでに使っているどのツールでもできます。

限界は、結果しか見えないことです。頼んだ内容はチャットの履歴に残るので、diff をその依頼の記憶と照らすことになります。

## 方法 2：先に別のエージェントへレビューさせる

自分で見る前に、別のエージェントへ diff をレビューさせます。たとえば、Claude Code が書いた内容を Codex に見てもらいます。明らかな問題を拾い、見る場所の一覧を出します。

そのレビューは第二の意見であり、承認ではありません。diff を読み、決めるのは今もあなたです。

## 方法 3：Coppice で、先に計画を承認する

[Coppice](/) は、コーディングエージェントを作業用のボードに置くデスクトップアプリです。コードを書く前に、エージェントが計画を書き、あなたが承認します。作業が終わると、Coppice は承認した計画の横に diff を出し、計画になかったファイルを示します。作業を受け入れてもマージはされません。いつメインブランチへ入れるかは、あなたが選びます。

1. [Coppice をインストール](/docs/install)し、プロジェクトを追加します。
2. チケットを書き、エージェントを動かします。PM エージェントが計画を書きます。
3. 計画を読みます。承認するか、修正を求めます。
4. チケットが Wait for Human Review（人によるレビュー待ち）に来たら、コードを確認します。行にコメントするか、作業を受け入れます。
5. 準備ができたらマージします。

見え方はこうです。チケットは Settings にダークモードのスイッチを付ける依頼です。PM エージェントの計画は 3 つの手順です。スイッチを足す、既存の theme hook を使う、設定のテストを足す。

![Plan Review にあるチケットです。タイトルは Add a dark mode toggle to Settings です。計画は Settings の行にスイッチを作り、3 つの手順を挙げます。Settings のスイッチを足す、既存の theme hook を使う、設定のテストを足す、です。](/blog/review-before-merging/plan-review.png "コードを書く前の計画です。")

作業が戻ると、承認した計画が diff の横にあります。目立つ点が 2 つあります。新しいコンポーネントは既存の theme hook を使わず、自分でテーマの状態を持っています。変わったファイルは 1 つだけなので、設定のテストはありません。受け入れる前に、どちらもコメントする価値があります。

![同じチケットのコードレビューです。左が承認済みの計画で、変わったファイルは src/settings/ThemeToggle.tsx だけです。useState の行の下のコメントは、既存の theme hook を使うよう求めています。](/blog/review-before-merging/diff-before-accept.png "承認した計画の横にある diff です。theme hook を飛ばした行にコメントがあります。")

[コンセプト](/docs/concepts)で、チケットが通る各ステップを説明しています。

## どれを選ぶか

- **1 つのエージェントによる小さな変更：** git か pull request でレビューします。
- **大きな変更で、先に一度見てほしい：** 別のエージェントに頼み、そのあと自分で読みます。
- **エージェントの作業が多く、コードを書く前に計画へ合意したい：** Coppice。まずは[はじめに](/docs/getting-started)。
