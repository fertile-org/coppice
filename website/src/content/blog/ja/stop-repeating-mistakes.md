## なぜ難しいのか

エージェントを訂正します。次のタスクは白紙から始まり、同じミスがまた出ます。チャットが終わると、コーディングエージェントはその訂正を残しません。次の実行の前にそれを置くか、ミスが戻ったときにチェックが失敗するか、どちらかが必要です。

## 方法 1：プロジェクトのルールファイル

Claude Code は、セッションの開始時に、起動したフォルダーとその上のフォルダーから `CLAUDE.md` を読みます。そのパスに `CLAUDE.md` も `CLAUDE.local.md` もないとき、代わりに `AGENTS.md` を読みます。自動メモリのファイル `MEMORY.md` からは、先頭 200 行か 25KB の、先に達したほうを読み込みます。Claude Code はこれらのファイルをコンテキストとして扱います。編集は止めません。

Codex は作業の前に `AGENTS.md` を読みます。プロジェクトのルートから、起動したフォルダーまで下り、結合したファイルが 32 KiB に達すると止まります。

Cursor は、プロジェクトのルートと、作業中のファイルがあるサブフォルダーの `AGENTS.md` を読みます。`.cursor/rules` のプロジェクトルールは、always apply にすると、すべてのチャットに入ります。そうでなければ、ファイルが一致するとき、エージェントが当てはまると判断したとき、またはあなたがそれを挙げたときに、Cursor が含めます。ルールファイルは助言です。エージェントは 1 行を飛ばすことができます。

## 方法 2：テストまたは lint のチェック

チェックがそのミスを見られるなら、チェックを足します。Settings のコントロールが自分のテーマ状態を持つと失敗するテスト、またはそのパターンの lint ルールは、次の実行でその変更を止めます。

これはミスを止めます。レイアウトの選択は、チェックが見られないので、今も人が必要です。

## 方法 3：タスクに書くか、skill に置く

訂正をこのタスクへ貼ります。エージェントはこの実行でそれを見ます。次のタスクには、もう一度貼る必要があります。

skill は短い手順のファイルです。タスクが合うとき、またはあなたが呼び出したときに、エージェントが読み込みます。Claude Code では、それまでファイルはセッションの外にあります。だから 1 行のルールは `CLAUDE.md` に、手順は skill に置きます。エージェントは今もそれを飛ばすことができます。

## 方法 4：Coppice で、承認する Knowledge のメモ

[Coppice](/) は、コーディングエージェントを作業用のボードに置くデスクトップアプリです。Knowledge は、後のチケットのための、プロジェクトについてのメモです。メモはあなたが書きます。チケットの作業中に、後のチケットが必要とするルールとして、エージェントがメモを提案することもできます。承認するまで保留のままです。後の実行は、保留中のメモを見られません。

メモは、すべてのボード、1 つのボード、またはボード上の 1 つのエージェントを対象にできます。エージェントがチケットから提案したメモは、そのボードを対象にします。

1. [Coppice をインストール](/docs/install)し、プロジェクトを追加します。
2. Knowledge を開き、メモを足します。Settings のダークモードのスイッチなら、コントロールは既存の theme hook を使い、変更には設定のテストが含まれる、と書きます。作業があるボードを選びます。
3. メモを承認します。
4. 次のチケットで、エージェントを動かします。Coppice は承認済みのメモを、チケットのタイトルと説明にある語で検索します。一致は実行の開始時にエージェントへ示され、それに頼る前に読むよう伝えられます。

後のチケットのタイトルが Add a dark mode toggle to Settings なら、それらの語を共有するので、メモは示されます。全文は、エージェントが読むまでプロンプトの外にあります。エージェントは承認済みのメモを検索することもできます。Coppice の外のターミナルは、そのメモを見ません。[コンセプト](/docs/concepts#knowledge)で Knowledge を説明しています。

## どれを選ぶか

- **ミスをチェックで失敗させられる：** テストか lint ルールを足します。
- **1 つのツールのすべてのセッションに短いルールを見せたい：** `CLAUDE.md`、`AGENTS.md`、または Cursor のルール。
- **1 つのタスク、またはすべてのセッションには置きたくない手順：** タスクに書くか、skill に置きます。
- **チケットが多く、次の実行が使う前に残す内容を承認したい：** Coppice。まずは[はじめに](/docs/getting-started)。
