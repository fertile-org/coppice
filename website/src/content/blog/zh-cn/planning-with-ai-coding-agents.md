## 为什么先做计划

智能体直接写代码时，理解错了只能在 diff 里看出来。到那时，它已经把不对的东西做出来了，你得花时间去读、解释你本来的意思，再等下一次尝试。一份计划把同样的误解收成几行字，一分钟就能读完。

拿到计划很容易：你开口要，任何智能体都会写。难的是让它有用。需求含糊，智能体不问就猜，计划只列步骤、不写背后的决定，一旦开始写代码，也没有人再对照计划检查。

## 一份好计划里有什么

- **用你自己的话写出结果和约束。**“Settings 里加一个深色模式开关，跟应用其余部分用同一套主题设置。”
- **要答案，不要猜测。** 智能体在做计划之前，先问它需要知道的事。
- **写出做法，以及为什么这样选。** 真有选择时，比如布局或数据模型，智能体列出选项并推荐一个。
- **几个步骤，包括能表明改动有效的测试。**
- **它不会改什么。**

如果一两分钟读不完，这个任务大概太大了。把它拆开。

## 做法一：CLI 里的计划模式

Claude Code 有计划模式：智能体读代码、提出计划，但不改文件。用其他智能体时，你要求一份计划，并告诉它在你批准之前不要改任何东西。

这是上手最快的做法。限制是计划只留在对话里。会话一结束，计划就没了，最终的 diff 也不容易再对照它检查。

## 做法二：仓库里放一份计划文件

让智能体把计划写进一个 Markdown 文件，比如 `docs/plans/dark-mode.md`。你自己改这个文件，再用 “Implement docs/plans/dark-mode.md” 开始实现。同一个智能体可以做，换一个也可以。

计划能留下来，跨过会话，也跨过不同的智能体，你还可以像审代码一样审它。文件仍由你管理，什么时候算批准由你决定，diff 和计划的对照也要你自己做。

## 做法三：用 Coppice，把计划做成你批准的一步

[Coppice](/) 是一个桌面应用，把编程智能体放在一块任务看板上。每张工单都从一份计划开始。PM 智能体可以先问你最多三个问题，再写计划。界面改动还会给出几种设计方案，供你比较和选择。这次规划不会改你的代码。你一批准，计划就保存在工单上，智能体按它来做，你再对照计划审核 diff。

1. [安装 Coppice](/docs/install)，并加入你的项目。
2. 写一张工单，写明结果和约束，然后让智能体开始做。
3. 如果 PM 智能体提问，就回答。
4. 读计划。如果是界面改动，打开设计方案并选一个。然后批准计划，或要求修改。
5. 代码准备好之后，对照已批准的计划审核 diff。

## 该选哪一种

- **一次会话里的小任务：** 计划模式。
- **跨会话或跨智能体的较大任务：** 一份计划文件。
- **任务很多，而且写任何代码之前，计划都是你要批准的一步：** 用 Coppice。从[快速上手](/docs/getting-started)开始。
