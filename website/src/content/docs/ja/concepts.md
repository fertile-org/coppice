# コンセプト

Coppice はコーディング作業のためのボードです。あなたがチケットを書き、エージェントがそれぞれのブランチで作業し、すべての変更はあなたのレビューを経てから取り込まれます。あなたが動くまで何も始まらず、あなたが選ぶまで何もマージされません。

<a id="how-a-ticket-moves"></a>

## チケットの流れ

1. **Backlog**（未着手）。チケットを作成するか、エージェントが提案したチケットを承認します。
2. **Plan Review**（計画レビュー）。**Run agent** を押すと、PM エージェントが計画を書きます。読んだうえで、承認するかコメントします。計画づくりでチケットのコードが変わることはありません。**Skip planning**（計画をスキップ）をオンにすると、チケットは Backlog から直接 Ready に進みます。フロー、アーキテクチャ、データモデルが関わる場合は、計画に小さな図が付くことがあります。文章の計画も必ずあります。
3. **Ready**（準備完了）。計画を承認すると、Technical Lead（テクニカルリード）エージェントが担当者を選びます。Technical Lead がいない、または適任者がいない場合、チケットは担当者なしのまま Ready に残り、コメントが付きます。
4. **In Progress、In Review、In QA**（作業中、レビュー中、QA 中）。エージェントがチケット専用のブランチで変更を作り、レビューし、テストします。あなたのメインのチェックアウトには触れません。
5. **Wait for Human Review**（人によるレビュー待ち）。diff を開いてコメントでフィードバックし、問題なければ **Accept**（承認）を選びます。その後エージェントがコミットを追加すると、チケットは In Review に戻り、再びあなたのところに来ます。
6. **Done**（完了）。承認してもマージはされません。準備ができたら **Merge…** を選びます。承認した内容が、そのままマージされます。ファイルが競合した場合、Coppice は main に手を付けず、チケットを In Progress に戻し、同じエージェントが競合を解決します。マージの前に、もう一度承認します。

行き詰まったチケットは **Blocked**（ブロック中）に移り、理由を書いたコメントが付きます。

<a id="agents"></a>

## エージェント

Coppice は、あなたがすでに使っているエージェント CLI（Claude Code、Codex、Cursor、OpenCode、Kilo Code など）を動かします。各エージェントには PM、Technical Lead、Backend Engineer などの役割があり、1 つの CLI で動きます。[プロバイダー](/docs/providers)を参照してください。

エージェントごとに別のモデルを使えます。同じ CLI でも構いません。PM は Claude Opus、Backend Engineer は Claude Sonnet、という使い分けができます。

<a id="chat"></a>

## チャット

**Chat** を開いてエージェントをクリックすると、コード、アイデア、チケットについて話せます。各エージェントは、あなたのすべてのリポジトリ、ボード、チケット、Knowledge を見られます。チケットの下書きや Knowledge のメモを提案することはできますが、あなたが承認するまで何も保存されません。別のチャットを始めるには **New chat** を選びます。

どの CLI でもチャットできます。Claude Code、Codex、Cursor、Kilo Code が読み取り専用のままかどうか Coppice はまだ確認できていないため、これらのチャットにはバナーが表示されます。エージェントは引き続きあなたのコンピューターでコマンドを実行できます。

<a id="everything-is-on-the-card"></a>

## すべてはカードの上に

コメント、計画、エージェントの実行はすべてチケットに残ります。エージェント同士はチケットのコメントを通してしかやり取りしないので、起きたことはそこで読めます。

<a id="knowledge"></a>

## Knowledge

エージェントは、後のチケットのためにプロジェクトについてのメモを残せます。既定では、何を残すかはあなたが承認します。
