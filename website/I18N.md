# Website languages

English is the default locale. Its URLs stay exactly as they are (`/`, `/download`, `/docs`, `/docs/concepts#chat`). The other locales are prefixes on those same paths:

| Language | `html lang` | URL prefix |
| --- | --- | --- |
| English | `en` | none |
| 简体中文 | `zh-CN` | `/zh-cn` |
| 繁體中文（台灣） | `zh-TW` | `/zh-tw` |
| 繁體中文（香港） | `zh-HK` | `/zh-hk` |
| 日本語 | `ja` | `/ja` |
| Français | `fr` | `/fr` |

The app UI (`web/`) is English-only. This note is only for the Astro site.

Nothing detects a language and nothing redirects to one. The switcher in the header is the only control. It opens the same page in the chosen language and keeps the hash.

## Fallback

A locale URL with no translation renders the English page and stays on that URL. `/ja/docs/install` shows the English install guide. For that page:

- `<html lang>` is the locale (`ja`).
- `<link rel="canonical">` is the English URL (`/docs/install`).
- The locale is left out of `hreflang` and out of `sitemap.xml`.
- The page is left out of that locale's docs search index.

`hreflang` lists only locales that have a real translation of that page, using `en`, `zh-CN`, `zh-TW`, `zh-HK`, `ja`, and `fr`, plus `x-default` pointing at English. English is always listed.

## Add a docs page

Add `website/src/content/docs/<locale>/<slug>.md` (`.mdx` works too). `<locale>` is the URL prefix (`ja`, `zh-cn`, `zh-tw`, `zh-hk`, `fr`). `index.md` is `/docs`. `concepts.md` is `/docs/concepts`.

```md
---
title: Concepts
description: One sentence for the meta description.
---

# Concepts

Write the translation here. Link other docs as English paths, for example [Install](/docs/install) or [Chat](/docs/concepts#chat).
```

Do not set `layout`. On the locale URL, the docs layout renders this file in place of the English article. The build prefixes root-relative doc links (`/docs/...`) on locale HTML, so write them as the English path.

A page file also counts as a translation: `src/pages/<locale>/docs/<slug>.md` with `layout: ../../../layouts/Docs.astro`. Prefer the content file. One file is enough.

## Homepage and download

`src/pages/<locale>/index.astro` is a shell so `/ja` (and the other locale homepages) can render. Leave those files in place.

- Homepage translation: `src/content/pages/<locale>/index.astro`. It is a full page and should render `Base` itself, the same way `src/components/HomePage.astro` does.
- Download translation: `src/content/pages/<locale>/download.astro`, or a page at `src/pages/<locale>/download.astro`.

## UI chrome

Copy `src/i18n/ui/en.ts` to `src/i18n/ui/<locale>.ts`. Export `locale` as the URL prefix (`'ja'`, `'zh-cn'`, …) and `ui` with the same keys: nav, docs sidebar, search placeholder and dialog, footer, skip link, and the switcher's accessible label. The folder is picked up automatically. If the file is missing, the chrome stays English. Replace the whole `ui` object; missing keys are not filled in from English.

The switcher names themselves live in `src/i18n/locales.mjs` (`English`, `简体中文`, `繁體中文（台灣）`, `繁體中文（香港）`, `日本語`, `Français`). They are not translated per page.

Docs search is a separate Pagefind index per locale. A locale with no translated docs returns no results. It does not search the English index.

## README

The language line at the top of the repo `README.md` links `README.zh-CN.md`, `README.zh-TW.md`, `README.zh-HK.md`, `README.ja.md`, and `README.fr.md`. Uncomment one link only after that file exists.

## Checks

`npm run check:i18n` checks the path helpers, then (after `npm run build`) compares `dist` to `scripts/english-routes.txt` and checks canonical and `hreflang` on a fallback page. It also builds once with a sample translation that is not part of the site, then deletes it.
