## Vocabulary and factual safeguards (updated without regional stereotypes)
- Preserve the prior rejection of universal 軟件/伺服器/預設 claims. Absence of 軟體 in a limited screen of the original selected set is not evidence that every source uses 軟件 or Hong Kong never uses 軟體. The repaired concentrated set does not change that logic.
- **HK47 L24 explicitly calls 數據 records**, while HK49 L25–28 calls structured data 資料. This directly defeats a fixed measurement-vs-records regional binary. No “資料 in the Taiwan sense” inference is accepted.
- **HK51 L14** uses 文件 for computer files; prior HK03/HK16 do too. Prefer 檔案 for file objects for project consistency, not because 文件 is impossible locally.
- **HK64 L9 程序** really denotes a software program, not only a procedure. Prefer 程式 in this project but do not call the source non-HK or mistranslated on that basis. HK60 L91 has 什麼; not just the original HK07 instance.
- English expansions are audience aids, not mandatory rituals. HK64 leaves routine technical nouns English-only. Product names are not all identifiers; only exact literal material requires exact code treatment.
- Neither accepted sources nor recognised writers guarantee correctness. HK50's “1–10000” text starts its code at 0; HK45's lifecycle order is inaccurate; HK51's date filename is not guaranteed unique; reserve HK48's code changes/has invalid identifiers. Security/privacy absolutes in HK46/HK65 and source marketing claims must not become Coppice assertions. Learning prose does not mean reproducing technical errors, typos, insults or hype.
